# KasDistro

KasDistro is a set of web tools for KCC-20 / KRC-20 tokens on Kaspa. Live site: [kasdistro.com](https://kasdistro.com).

| Page | Path | What it does | Needs the backend? |
| --- | --- | --- | --- |
| Landing | `/` | Marketing page, price and distribution charts | No |
| Distro | `/distro` (also `/dispenser`) | Import token holders, then send tokens to many wallets in batches | Holder import: no. Sending: **yes** |
| Kaspaper | `/kaspaper` | Paper-wallet tool | No |
| Volume Bot | `/volume-bot` | Wallet sign-in and per-user trading bot dashboard | **Yes** (plus a database) |
| Testnet Lab | `/testnet-lab` | Read-only token inspection on Kaspa testnet | **Yes** |

## Current hosting status (read this first)

- **The frontend** is a static Vite + React app hosted on **Vercel**. It is built from the `main` branch of this repo, and every push to `main` redeploys it.
- **Vercel serverless functions:** there is only one, `api/kron/token-holders/[identifier].ts`, which powers holder import on `/distro`.
- **The Express backend** (`artifacts/api-server`) is **not deployed anywhere right now**. It used to run on Replit, and that app has been shut down. Until it's hosted again, these features return `404` on the live site:
  - Sending tokens from `/distro` (`POST /api/kaspa/build-pskt`)
  - Everything on `/volume-bot` (`/api/app/*`, `/api/bot/*`)
  - `/testnet-lab` (`/api/kron/testnet/inspect`)

To bring those back, see [Hosting the backend](#hosting-the-backend).

## Tech stack

- **Monorepo:** pnpm workspaces (`pnpm-workspace.yaml`), with shared dependency versions in the `catalog:` section
- **Frontend:** React 19, Vite 7, Tailwind 4, Radix UI, TanStack Query, wouter (routing)
- **Backend:** Node + Express 5, pino logging, `@kronsdk/kron-sdk` for Kaspa/KRON transactions
- **Database:** PostgreSQL through Drizzle ORM (only needed for Volume Bot)
- **API contract:** OpenAPI spec in `lib/api-spec/openapi.yaml`, with the React Query client and Zod schemas generated by Orval

## Running locally

Requirements: **Node 22+** (Vercel uses Node 24) and **pnpm 10+**. npm and yarn are blocked by a `preinstall` check.

```sh
pnpm install
```

**Website only.** Holder import works locally because the Vite dev server serves that endpoint itself:

```sh
PORT=5173 BASE_PATH=/ pnpm --filter @workspace/kaspa-disperse run dev
```

**Website + backend** (needed for sending, Volume Bot and Testnet Lab). Run these in two terminals:

```sh
# Terminal 1: backend on port 5000
PORT=5000 pnpm --filter @workspace/api-server run dev

# Terminal 2: website; the dev server proxies /api to the backend
PORT=5173 BASE_PATH=/ API_PROXY_TARGET=http://127.0.0.1:5000 pnpm --filter @workspace/kaspa-disperse run dev
```

Then open http://localhost:5173.

**Type-check and build everything:**

```sh
pnpm run build
```

## Environment variables

Never commit real values. This repo is **public**.

### Website (Vercel project → Settings → Environment Variables)

| Variable | Required | Purpose |
| --- | --- | --- |
| `VITE_API_BASE_URL` | Only once the backend is hosted separately | Public URL of the Express backend, e.g. `https://api.kasdistro.com`. The site calls `<this>/api/...`. If unset, it calls the same domain. It's baked in at build time, so redeploy after changing it. |

`PORT` and `BASE_PATH` are also required by the Vite config, but `scripts/vercel-build.mjs` sets defaults for them on Vercel.

### Backend (`artifacts/api-server`)

| Variable | Required | Purpose |
| --- | --- | --- |
| `PORT` | Yes | Port the Express server listens on |
| `NODE_ENV` | Recommended | Set to `production` in production (secure cookies, JSON logs) |
| `DATABASE_URL` | For Volume Bot | Postgres connection string. Without it, the `/api/app/*` routes and the bot schedulers are disabled. |
| `SESSION_SECRET` | For Volume Bot | Long random string used to sign user session cookies |
| `KASPA_BOT_PRIVATE_KEY` | For the house bot | Private key of the dedicated bot wallet. **This key controls funds.** Store it only in the host's secret manager. |
| `KRON_TOKEN_ID` | For the house bot | KCC-20 token ID the house bot trades |
| `LOG_LEVEL` | No | pino log level (default `info`) |

### Dev-only

| Variable | Purpose |
| --- | --- |
| `API_PROXY_TARGET` | Where the Vite dev server proxies `/api` (default `http://127.0.0.1:5000`) |
| `API_URL` | Backend URL used by the `test:pskt` script |

## Deployment (Vercel)

Vercel is set up through `vercel.json`:

- Install: `pnpm install`
- Build: `node ./scripts/vercel-build.mjs` (builds `@workspace/kaspa-disperse`)
- Output: `artifacts/kaspa-disperse/dist/public`
- All non-`/api` paths are rewritten to `index.html` so client-side routes work
- The holder function gets a 60-second timeout

Pushing to `main` deploys to production. Pull requests get preview deployments.

Domains: `kasdistro.com` and `www.kasdistro.com` are attached to the Vercel project.

## Hosting the backend

The Express server is a normal long-running Node process. It runs background schedulers, so it isn't suited to serverless. Any Node host works: Railway, Render, Fly.io or a small VPS.

1. Build: `pnpm install && pnpm --filter @workspace/api-server run build`
2. Start: `pnpm --filter @workspace/api-server run start` (serves `dist/index.mjs`)
3. Set the backend environment variables listed above on the host.
4. For Volume Bot, provision Postgres, set `DATABASE_URL`, then create the tables:
   `pnpm --filter @workspace/db run push`
5. Give it a public URL (e.g. `api.kasdistro.com`), set `VITE_API_BASE_URL` to that URL in Vercel, and redeploy the frontend.

The backend allows cross-origin requests with credentials. Volume Bot's session cookie is `SameSite=Lax`, though, so host the API on a **subdomain of `kasdistro.com`** (like `api.kasdistro.com`). A completely different domain would cause the browser to drop the login cookie.

## Changing the API

1. Edit `lib/api-spec/openapi.yaml`.
2. Regenerate the client and schemas: `pnpm --filter @workspace/api-spec run codegen`
3. Implement the route in `artifacts/api-server/src/routes/`.

## Notes and leftovers

- `artifacts/api-server/src/lib/distributor-poc/` is an **unaudited experiment** with its own README. It isn't used by the live send flow, and it isn't safe for deposits.
- Some Replit-era bits remain and are harmless: the `@replit/connectors-sdk` dependency, the `@replit/vite-plugin-*` catalog entries, and a `REPL_ID` check in `mockup-sandbox`. They can be removed in a cleanup pass.
